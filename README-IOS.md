# Melody Music iOS

This folder contains the iPhone application shell for Melody Music.

## App identity

- App name: `Melody Music`
- Bundle ID: `com.glory.melodymusic`
- Version: `1.0.0`
- Production site: `https://babavs.edu.kg/`
- Capacitor: `8.4.2`

## Generate the Xcode project on a Mac

Requirements: macOS, Xcode, Node.js 22+, and an internet connection.

```bash
cd ios-app
npm install
npx cap add ios
npx cap sync ios
bash scripts/configure-ios.sh
npx cap open ios
```

Capacitor 8 generates the Xcode project at `ios-app/ios/App/App.xcodeproj`. The project uses Swift Package Manager for Capacitor plugins, so this repository does not rely on an `App.xcworkspace` generated by CocoaPods.

## Required iOS capability

The configuration script adds `UIBackgroundModes` with the single value `audio`, which is required for background music playback.

Do not request microphone, camera, location, contacts, push notification, CarPlay, subscription, or offline-download permissions/features for version 1.0.

## Local simulator verification

After generating and syncing the iOS project:

```bash
cd ios-app
xcodebuild \
  -project ios/App/App.xcodeproj \
  -scheme App \
  -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO \
  build
```

The repository also contains `.github/workflows/verify-ios.yml`, which performs the web/account contract tests, builds the native audio Swift package for the iOS Simulator, generates/syncs the Capacitor project, verifies background audio configuration, and builds the generated iOS app.

## Signing and App Store / TestFlight

Before TestFlight/App Store delivery:

1. Enroll the Apple ID in the Apple Developer Program.
2. Register or confirm the App ID `com.glory.melodymusic`.
3. On a Mac, run the generation/sync commands above and open `ios-app/ios/App/App.xcodeproj` in Xcode (or run `npx cap open ios`).
4. Select the correct Apple Developer Team under **Signing & Capabilities**.
5. Confirm Background Modes includes audio playback and that unrelated permissions are not enabled.
6. Confirm the public Privacy Policy and Terms of Use pages open correctly.
7. Archive the app with **Product > Archive**.
8. Upload the archive from Xcode Organizer to App Store Connect.
9. Test the uploaded build through TestFlight before production submission.

The project must be tested on a real iPhone for background playback, lock-screen metadata/artwork, Control Center commands, AirPods/Bluetooth commands, phone/audio interruptions, screen lock, and returning from the background.

From the repository root:

```bash
node --test test/ios-config.test.mjs
node --test test/ios-bridge.test.mjs
node --test test/ios-playback-adapter.test.mjs
node --test test/ios-mobile-ui.test.mjs
node --test test/ios-release.test.mjs
node --test test/user-account-delete.test.mjs
```

The full repository `npm test` currently also includes pre-existing Android/upload tests unrelated to this iOS feature. The iOS workflow therefore runs the iOS/account test set explicitly and separately verifies the native iOS build.

## Real-device acceptance checklist

Before calling version 1.0 ready for App Store submission, verify on a physical iPhone:

- Home loads songs and albums.
- Album playback uses the expected queue.
- Search finds song/artist/album content.
- Public playback works while signed out.
- Registration/login works against the production backend.
- Favorites, playlists, and play history work while signed in.
- Timed LRC highlights and scrolls with playback.
- Plain lyrics display completely when no timed LRC exists.
- Music continues when the screen locks or the app moves to the background.
- Lock screen shows the correct song information and artwork.
- Lock-screen/Control Center play, pause, next, previous, and seek work.
- AirPods/Bluetooth media controls work.
- Returning to the foreground reflects the true native playback state.
- Privacy Policy and Terms of Use open.
- The in-app account deletion flow removes the account and signs the user out.
